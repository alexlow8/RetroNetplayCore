// ============================================================================
// RING BUFFER LIFECYCLE
// ============================================================================

/*
Ring buffer is a circular array: [0][1][2]...[255]
Allocate once at startup, reuse forever.

Frame 0 arrives from network:
  store_at = 0 & 0xFF = 0
  _inputRingBuffer[0] = frame0_data

Frame 1 arrives:
  store_at = 1 & 0xFF = 1
  _inputRingBuffer[1] = frame1_data

...many frames...

Frame 256 arrives (wraparound!):
  store_at = 256 & 0xFF = 0
  _inputRingBuffer[0] = frame256_data  ← Overwrites frame 0's data

This is OK because:
  - Frame loop is at frame 256
  - Frame 0 is ancient history (256 frames ago = 4+ seconds ago)
  - Frame 0 data will never be read again

SIZE: 256 slots × sizeof(HostFramePacket) ≈ 13 KB
ALLOCATION: One-time at startup, then reused forever
*/


// ============================================================================
// THREAD ARCHITECTURE
// ============================================================================

/*
RetroNetplayCore has TWO threads:

THREAD 1: MAIN (60 FPS Frame Loop)
├─ Responsibility: Run emulation at precise 60 FPS
├─ Allocation: ZERO (all pre-allocated)
├─ Runs: Input capture → sync → emulation
├─ Waits on: Nothing (non-blocking)
└─ Calls:
   ├─ InputManager.CaptureFrame()
   ├─ NetworkThreadManager.PublishLocalInput() [non-blocking queue]
   ├─ NetworkThreadManager.GetFrameInputs() [read pre-filled buffer]
   └─ EmulatorManager.UpdateFrameStates()

THREAD 2: NETWORK (Background)
├─ Responsibility: Handle all network I/O
├─ Allocation: Allowed (not frame-critical)
├─ Runs: Receive → deserialize → store
├─ Runs: Serialize → send
├─ Runs: Monitor heartbeat timing
├─ Waits on: Socket receive (with timeout)
└─ Calls:
   ├─ Socket.ReceiveFrom()
   ├─ Socket.SendTo()
   ├─ JsonSerializer (for server msgs)
   └─ WriteToRingBuffer()

SYNCHRONIZATION:
├─ Ring buffer: Thread-safe (single reader, single writer, atomic ops)
├─ Outgoing queue: May use lock or lock-free queue
├─ No locks on frame-critical path
└─ CancellationToken to shut down cleanly
*/

/*
FRAME LOOP:
├─ FPS: 60 (target)
├─ Frame time budget: 16.67 ms
├─ Time per frame: ~15 ms available (1.67 ms margin for OS)
├─ GC pauses: 0 (zero allocation!)
└─ Consistency: ± 0.5 ms variance acceptable

NETWORK THREAD:
├─ Heartbeat interval: 1000 ms
├─ Heartbeat timeout: 3000 ms (server side)
├─ P2P packet rate: ~60/sec (one per frame)
├─ P2P packet size: ~50 bytes (estimate, TBD)
├─ Outgoing queue depth: Keep < 10 frames
└─ No strict latency budget (runs in background)

MEMORY:
├─ Ring buffer: 13 KB
├─ Peer endpoints: 1 KB
├─ Outgoing queue: ~10 KB (max 10 frames)
├─ Total overhead: ~25 KB
└─ Zero additional allocation during gameplay

LATENCY TARGET:
├─ Frame-to-frame: < 100 ms (acceptable for action games)
├─ P2P one-way: 15-50 ms (internet/LAN)
├─ Server heartbeat: Async, not critical path
└─ Dropout detection: 3+ seconds (acceptable)
*/
